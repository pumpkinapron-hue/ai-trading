# ADR（Architecture Decision Records）

後から「なぜこうなっているのか」を追えるようにするための記録。
設計を変えたくなったとき、当時の前提が今も成り立つかを確認するために使う。

## 書き方

`NNNN-短い題名.md` の形式で追加する。既存のADRは書き換えず、
判断が覆った場合は新しいADRを起こして `Supersedes: NNNN` を記す。

```markdown
# NNNN. 題名

- 日付: YYYY-MM-DD
- 状態: 採用 / 却下 / 廃止 / 置換（Supersedes: NNNN）

## 背景
何を決める必要があったか。

## 決定
何に決めたか。

## 理由
なぜそれを選んだか。却下した選択肢とその理由も書く。

## 影響
この決定によって何が制約されるか。
```
